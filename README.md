# MuckiSafeAgentPlugin

Composer package: `muckiware/mucki-safe-agent-plugin`

Optional Shopware 6 plugin that provides the **agent control plane** for
MuckiSafe: provisioning and supervision of host agents, declarative actions
and parameter schemas, Facility repository hooks, backup runs, job queue,
agent API, wakeup files and its own administration, ACL and audit.

`MuckiFacilityPlugin` stays the general backup plugin — all agent
functionality lives here. The PHP plugin and the Go agent (`agent/`) share
this repository but are built and released separately; Shopware installations
never need a Go toolchain.

* Design document: `docs/design.md`
* Normative implementation contract: `docs/implementation-plan.md`

## Facility dependency

| Requirement | Enforced by |
|---|---|
| Plugin activation requires an installed, **active** `MuckiFacilityPlugin` >= `0.11.0` (the version shipping the neutral `BackupFinishedEvent`) | Shopware requirement validation on the composer requirement `muckiware/facility-plugin: ^0.11` **plus** the `FacilityDependencyGuard` inside `MuckiSafeAgentPlugin::activate()` |
| Facility must not be removed while this plugin is installed | Composer dependency graph (`composer remove muckiware/facility-plugin` fails) |
| Facility must be deactivated/uninstalled **after** this plugin | Shopware refuses deactivation/uninstallation of Facility while this plugin is active (`FRAMEWORK__PLUGIN_HAS_DEPENDANTS`) |

**Documented lifecycle:** deactivate/uninstall `MuckiSafeAgentPlugin`
first, then `MuckiFacilityPlugin`. Reverse the order to install.

### Fail-closed state `facility_unavailable`

If Facility ends up inactive despite the protections above (for example
through a direct database change), the agent administration, API and
subscribers fail closed into the state `facility_unavailable`
(`FacilityDependencyGuard::STATE_FACILITY_UNAVAILABLE`): no new jobs are
created, a health error is shown, existing jobs are never deleted.

```php
// Service tag-free usage — the guard is registered as its class name.
$guard = $container->get(\MuckiSafeAgentPlugin\Service\Plugin\FacilityDependencyGuard::class);

if (!$guard->isFacilityAvailable()) {
    // fail closed — see FacilityDependencyException::getReason() for details
    $guard->assertFacilityActive(); // throws FacilityDependencyException
}
```

* PHP ~8.3.0 || ~8.4.0 || ~8.5.0 with `ext-sodium`

## Tests

```bash
composer validate --strict
composer test:unit         # tests/Unit — mocked Shopware classes, no kernel, no database
composer test              # unit + integration (integration needs an installed Shopware, see below)
```

Unit tests run without a Shopware installation when the plugin has a
plugin-local vendor directory (`composer install` inside the plugin), or
against the vendor directory of a surrounding Shopware checkout
(`phpunit --testsuite Unit --configuration=custom/plugins/MuckiSafeAgentPlugin/phpunit.xml.dist` from the Shopware root).

### Integration test harness

DAL, migration, route and boot tests run **only** inside an installed
Shopware instance. The harness provisions it reproducibly:

```bash
tests/Integration/run-shopware.sh --shopware v6.6.10.32 --mysql 8.0
tests/Integration/run-shopware.sh --shopware v6.7.16.1 --mysql 8.4
```

It starts MySQL 8.0/8.4, checks out `shopware/production` at the supported
tag, places `MuckiFacilityPlugin` (tag from `MUWA_TEST_FACILITY_REF`,
default `v0.11.0`) and this plugin checkout under `custom/plugins/`, runs
`composer install`, `system:install`, `plugin:refresh`,
`plugin:install --activate` for both plugins and finally PHPUnit from the
Shopware root with this plugin's configuration.

**Execution modes** (selected automatically):

* **native** — `php` + `composer` on `PATH` (CI runner). MySQL either from a
  docker container started by the harness (ports 3380 / 3384) or from a
  pre-provisioned endpoint via `TEST_DATABASE_URL`.
* **ddev** — no host PHP (development Mac): the inner phase runs inside the
  DDEV web container via `ddev exec`; MySQL runs as a host docker container
  reachable through `host.docker.internal`.

**Environment contract** (identical in `tests/bootstrap.php`,
`tests/Integration/run-shopware.sh` and the CI workflow `php-tests.yml`):

| Variable | Meaning | Default |
|---|---|---|
| `TEST_DATABASE_URL` | `mysql://user:***@host:port/database` for the integration kernel and `system:install` | generated by the harness |
| `MUWA_TEST_WORKSPACE` | working directory for the harness checkouts | `/tmp/muwa-integration` |
| `MUWA_TEST_FACILITY_REF` | `MuckiFacilityPlugin` tag used by the harness | `v0.11.0` |
| `MUWA_TEST_KEEP_MYSQL` | `1` = keep the MySQL container running between runs | unset |

`--fresh` discards the cached Shopware workspace and rebuilds it from
scratch.
